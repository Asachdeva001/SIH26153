# Backend Implementation Audit

Audit basis: the supplied Colab ground truth and the repository state inspected on 2026-09-27. This audit is read-only with respect to the existing implementation; the only file added by this pass is this report.

## 1. Executive Summary

The backend is **not currently consistent** with the Colab-trained model contract. The checked-in checkpoint is structurally compatible with a 25-feature, two-layer LSTM with hidden size 64 and embeds `history_len=4`, but the runtime model still has an internal sigmoid and the local training path still uses `BCELoss`; this is semantically incompatible if the Colab checkpoint was trained with raw risk logits and `BCEWithLogitsLoss`. Real CIC-IDS-2018 uploads are also not handled according to the stated parser contract: duplicated header rows are not removed, broad numeric coercion is absent, and the exact CIC label mapping is missing. The checked-in benchmark report is explicitly synthetic, and the benchmark API still computes request-time metrics rather than serving an offline report. Loading the checkpoint may succeed at the state-dict level because sigmoid has no parameters, but predictions can be wrong without raising a load error.

## 3. Critical Mismatches (fix these first)

1. **Risk-head semantics:** [backend/src/world_model.py](backend/src/world_model.py#L24-L31) has `nn.Sigmoid()` in the model, while the supplied trained contract requires a raw logit. Because sigmoid has no learned parameters, `load_state_dict()` can succeed and still produce semantically wrong risk values.
2. **Inference conversion missing:** [backend/src/world_model.py](backend/src/world_model.py#L200-L208) does not apply `torch.sigmoid()` to the raw risk output.
3. **Training recipe mismatch:** [backend/src/world_model.py](backend/src/world_model.py#L101-L120) uses `BCELoss()` and a `2.0` risk weight, not the specified `BCEWithLogitsLoss`, class-imbalance `pos_weight`, risk weight `5.0`, and state-loss normalization.
4. **Real CSV ingestion mismatch:** [backend/src/parser.py](backend/src/parser.py#L68-L129) lacks the required duplicated-header filtering and broad numeric coercion; the exact CIC label set is also missing at [backend/src/parser.py](backend/src/parser.py#L13-L27).
5. **Silent synthetic fallback:** [backend/models/loader.py](backend/models/loader.py#L18-L35) catches every checkpoint-load exception and serves a newly fitted synthetic model. This can conceal a real-model incompatibility and produce misleading forecasts.
6. **Working-directory-sensitive artifact paths:** [backend/models/loader.py](backend/models/loader.py#L18-L21) uses `models/...` relative to the process working directory, while the checked-in artifacts are under `backend/models/`. Starting Uvicorn from the repository root can therefore trigger synthetic fallback.

## 4. Needed Changes, Prioritized

- 🔴 **Blocks or can silently invalidate real-model inference:** align `PyTorchTransitionLSTM` with raw logits, apply sigmoid only in inference, reproduce the Colab loss for local training, validate checkpoint dimensions/history, and make artifact paths absolute/repository-relative. Remove or make synthetic fallback explicit and fail-fast for production.
- 🔴 **Blocks reliable real CSV use:** add duplicated-header filtering, numeric coercion with invalid-row removal, and exact CIC-IDS-2018 label keys. Review severity values against the Colab mapping rather than assuming the current values.
- 🟠 **Misleading evaluation:** change `/api/benchmark` to read and return an offline `benchmark_report.json` plus optional cross-validation results. Do not calculate F1, precision, recall, or FPR from request-time forecast windows.
- 🟠 **Potentially misleading XAI:** ensure the explainer's target output and baselines use the same raw-logit/probability convention as the trained model, and document whether synthetic background data is intentional.
- 🟡 **Missing tests:** add tests for checkpoint architecture/output semantics, exact label coverage, embedded header removal, numeric coercion, artifact-path loading, and benchmark report serving.
- 🟡 **Documentation:** document the CSV defaults for TTL/TCP window/IP fragmentation and the hardcoded retransmission ratio limitation in the project documentation.
- 🟢 **Cleanup:** no root-level stale `Dockerfile`, `Procfile`, or `render.yaml` exists in this checkout. Keep the current backend Dockerfile/Compose setup unless deployment targets require new files.

## 5. Open Questions for the Human

1. Was the retained Colab checkpoint definitely trained with `history_len=4`, or was the intended experiment `history_len=8`? The checked-in checkpoint embeds `4`, but source/artifact inspection cannot establish which Colab run produced it.
2. Is `backend/models/world_model_v1.pth` the Colab-trained CIC-IDS-2018 checkpoint, or a local synthetic fallback artifact? Its architecture metadata is compatible, but the file contains no dataset provenance; the only checked-in benchmark report explicitly says synthetic.
3. What exact severity values did the Colab training use for the 15 CIC labels? The current mapping is incomplete, so values should be supplied or re-derived before changing it.
4. Should the API fail when the real checkpoint is absent/incompatible, or is synthetic fallback intentionally retained for development? The current fallback makes production/data-quality failures easy to miss.
5. Which working directory is the supported manual launch location? The loader currently uses paths relative to the process current directory, while artifacts live under `backend/models/`.
6. Where should the offline `benchmark_report.json` and optional `cv_results.json` be stored and what response schema should the frontend consume?
